## 1. 已锁定的做法

产品仍是 3–8 分钟一局的纯 Web 工艺流程。运行环境、性能基线、输入和存档以设计文档 §1.4、§1.5 为准。

### 1.1 技术栈

- Vite + TypeScript + Three.js。界面用 React。
- 三维场景在 `requestAnimationFrame` 中更新，不随 React 每帧重绘。
- 设计文档允许 Cocos 发布 Web。本计划锁定 Three.js，因为正式资产是 PNG、SVG、glTF 和 JSON，按 id 替换，不经过编辑器资源库。
- 杯体是车削曲面（约 64 环 × 48 段）。拉坯直接改各环的半径和高度，不使用实时布尔。每个受力点的泥体积固定，壁厚由当前半径和点距反解。
- 转台、晾坯架、窑按杯高 1 个单位制作。
- 窑变贴图在开窑动画期间生成，不预画成品贴图。
- 模拟内核是纯函数。没有画面也能跑完一局状态。

### 1.2 语音与音效

- 旁白是可跳过的文字，合计约 400 字，按玩法环节拆开。
- 音效文件不制作、不采购。
- 程序保留按 id 取音频的空总线。找不到文件就静音，不抛错。以后把路径填进清单即可发声，不必改玩法。
- 状态条、外形变化和文字从环节 1 起就是完整提示。听障与静音是默认路径，不是附加模式。

### 1.3 占位与替换

- 编码从占位色、基本体和内置 SVG 开始。美术文件不是前六个开发环节的门槛。
- 玩法代码只认识字符串 id。路径只出现在 `src/assets/manifest.ts`。
- 正式文件放在 `public/assets/art/`。该目录可以为空，空目录不影响构建。
- `pnpm check:assets` 从环节 1 起执行：代码引用的每个 id 都在清单中，清单的每一项都有占位。

## 2. 开发环节

七个环节顺序执行。上一个环节的退出标准达成后，再进入下一个。灰度放在环节 7 之后。当前仓库已完成环节 1–5，正在环节 6。

| 环节   | 内容                                     | 退出标准                                               |
| ------ | ---------------------------------------- | ------------------------------------------------------ |
| 环节 1 | 工程骨架与资产登记                       | 五个玩法环节的空场景能切换；缺文件不崩溃               |
| 环节 2 | 模拟内核                                 | 同一种子加同一操作序列，结果逐字相同                   |
| 环节 3 | 调配陶土、拉坯塑型                       | 水土比能把杯子拉塌；不规定器形、不计时；确认后进入晒干 |
| 环节 4 | 晒干素烧、配釉施釉、成型煅烧与 16 条事件 | 能从调泥走到开窑；失败都落在外形上                     |
| 环节 5 | 窑变、存档、分享                         | 刷新能续玩；同一链接还原同一只杯                       |
| 环节 6 | 引导、知识卡与兼容                       | 无声、色弱、无 WebGL、手机浏览器都能走完主流程         |
| 环节 7 | 正式资产替换                             | 换图、换模、换文案都不改玩法代码                       |

环节 4 是工作量中心。拉坯手感在环节 3 收束，材质放到环节 7。

### 环节 1 · 工程骨架与资产登记

- Vite + TypeScript + Three.js，HUD 用 React。
- 建立 AssetRegistry。玩法只调用 id。`src` 为空就走占位，并在控制台记一次缺失 id。
- `GameState` 带 `schemaVersion`。计时用 `performance.now()` 差值。监听 `visibilitychange`，切到后台就冻结本局时钟，回来不追帧。
- 严格类型。`pnpm check:assets` 进入常规验证。

**本环节你可交出的参考（没有也能开工）**：色板、杯形侧面、泥面近拍、已有的工坊或杯子照片。这些参考不进游戏包。

### 环节 2 · 模拟内核

- 纯函数，不依赖 WebGL：配泥 P/H/I/C、稳定性 S、阴干耦合、素烧偏离、火候曲线、窑变。
- 随机只走种子 RNG。操作序列作为附加盐。分享链接携带种子、操作摘要和 `schemaVersion`。
- Vitest 覆盖公式、事件次数上限（阴干 0–2、素烧 0–1、煅烧 0–1）、存档迁移失败时的降级。
- 调试面板显示 P、H、I、S。数值全部来自 `data/*.json`，设计文档中的数字原样当占位。

### 环节 3 · 调配陶土、拉坯塑型

- 杯体是车削曲面。拉坯改各环的半径和高度。每个受力点的泥体积固定，壁厚随半径和点距变化，使旋转体体积保持不变。
- **玩法环节「调配陶土」**：三种泥料与水量滑块。揉泥 3 秒用连点节奏，只有视觉圈。水量为 0 判劣，但允许继续。
- **玩法环节「拉坯塑型」**：右键看杯，滚轮或滑条调转速（0–800）。左键按住拖动，箭头指向运动方向，杯壁沿该方向变形；向上托时，接触点以上的泥一起走。可切换整体 / 内外 / 抹平三种手法。不规定器形，不计时。虚影只作对照。杯壁按受力实时判定是否撑住，撑不住就塌。塌了可以重做这一步、回去调泥或重开一局。确认后直接进入晒干。
- 本环节末找 5 名内部试玩拉坯，认可手感后再冻结跟手的力度。
- 桌面拖拽与触屏单指拖拽走同一套指针逻辑。

### 环节 4 · 晒干素烧、配釉施釉、成型煅烧与事件

- 事件写成 JSON。处理函数是封闭集合：盖布、搬高、包裹、等待、改风向、补裂纹、固定支架、放缓升温、推迟入窑、窑内换位、加大进气、关门缓冷、调气氛、延长保温。
- 事件 5（风扇直吹）和事件 12（高温开窑门）是玩家主动误用，不是随机弹窗。其余事件按设计文档的概率与预兆时间触发。
- 阴干不可加速。湿度每升高 10%，阴干时长 +8%，素烧排湿目标带宽度收窄 15%。新手前 3 局事件概率减半，预兆延长到 4 秒。
- **玩法环节「配釉施釉」**：六种釉任选两种，浓度与 1–3 层。笔刷把圆形图章画进车削 UV 遮罩。总层数 > 4 记下挂足风险。均匀度低于 40% 只提醒，不阻断。
- 瑕疵用几何咬边加着色器图案，贴图 id 预留。开窑约 6 秒，镜头转一圈后给出器形、釉色、编号、知识卡数。
- 弹层文案用师傅口吻，写出成因、外形后果、下次如何避免。用词避开「你错了」「失败」「笨」。

### 环节 5 · 窑变、存档、分享

- 开窑动画期间在 Worker 里生成 1024² 反照率与粗糙度，预算 800ms。超时则降到 512²。结果以 PNG 进入 IndexedDB，LRU 上限 32。离开玩法环节时 `dispose` 几何与材质。
- 唯一性输入：种子、含铁量、釉方、峰值温度、保温、气氛、杯体几何哈希。连续抽样 1000 个种子，完全同款数为 0。
- 存档时机：玩法环节完成、主动退出、每 30 秒。localStorage 失败则只留在内存里，本局继续。旧 schema 读失败时重开一局，并赠送知识卡 ×3。
- 分享图用画布合成。边框资产缺失时用程序边框。链接不含服务端。服务端校验留到灰度之后。

### 环节 6 · 引导、知识卡与兼容

- 师傅台词约 400 字，按玩法环节拆开，可一键跳过。不播放语音。（已有）
- 知识卡带来源章节。通关弹出。次日复访用本地日期抽问，答对写入档案。（已有）
- 状态条始终带数字和文字。色弱模式下，塌陷、开裂、针孔同时有图案。（Meters 已支持 `pattern`；**独立色弱开关待做**）
- 无 WebGL 2 时进入静态图文页。连续 3 帧超过 50ms，就降低粒子数量和贴图分辨率一档。转台与施釉区设置 `touch-action: none`。（降级与降帧已有；指标待实测）
- 首屏只加载玩法环节「调配陶土」，其余玩法环节动态 `import`。首屏 gzip ≤ 3MB。4G 模拟下首次可交互 ≤ 2.5 秒。
- 裁定 HUD「跳过这步」是否进入正式产品。

### 环节 7 · 正式资产替换

- 正式文件放入 `public/assets/art/`，只改清单里的 `src`。材质按名字绑定，节点按约定名字查找。
- 替换验收：删掉某张正式图会退回占位；换一张不同分辨率的贴图仍能显示，并在控制台警告一次。
- 文化文案在本环节定稿。名称、口诀、知识卡来源留审核记录。
- 灰度不放在本环节内，放在文案定稿之后。

### 环节之后 · 灰度

约 100 名浏览器用户。对照设计文档 §1.2：新手首通率 ≥ 55%；塑型、施釉、窑变的次日复访率 ≥ 25%。通关知识卡能说出揭阳陶塑至少两个特征。

服务端只在灰度之后考虑，用来校验分享结果是否合理，不参与局内过程。离线仍可单机通关。

| `content/knowledge-cards.json` | 知识卡至少 8 张，每张注明来源章节                     |

### 3.6 本阶段不准备

| ------------------- | -------------- | -------------------------------- |

## 4. 替换约定

### 4.1 换一张图

把文件放到清单写明的路径，或只改该条的 `src`。分辨率可以不同，加载时会用，并在控制台警告一次。PBR 的 albedo、normal、roughness 必须成套替换。

### 4.2 换一个模型

glTF 2.0，Y 轴向上，杯高对应 1 个单位。代码按节点名和材质名取物体，不使用子节点序号。

| 模型     | 节点                                           | 材质                            |
| -------- | ---------------------------------------------- | ------------------------------- |
| 拉坯转台 | `wheel_head`                                 | `wood`、`metal`             |
| 晾坯架   | `rack`                                       | `wood`                        |
| 窑       | `kiln_shell`、`kiln_door`、`kiln_cotton` | `brick`、`door`、`cotton` |

### 4.3 找不到正式文件时

| 种类 | 行为                       |
| ---- | -------------------------- |
| 贴图 | 使用清单里的纯色或程序图案 |
| 模型 | 使用圆柱、盒子等基本体     |
| 图标 | 使用仓库里的内置 SVG       |
| 字体 | 使用 `system-ui`         |
| 音频 | 静音，不抛错               |
| 文案 | 显示 id，便于发现漏译      |

### 4.4 禁止出现的写法

- 组件里写死 png、glb、mp3 路径。
- 用 `children[0]` 或材质数组下标去认模型部件。
- 把配方、季节湿度和师傅台词写进 TypeScript 字符串。
- 窑变结果依赖某张预先画好的成品贴图才能显示。

## 7. 风险

| 风险                   | 环节        | 做法                                             |
| ---------------------- | ----------- | ------------------------------------------------ |
| 拉坯太灵或太钝         | 环节 3      | 五人试玩后再冻结跟手的力度                       |
| 形变时体积漂移         | 环节 3      | 壁厚由定点体积、当前半径和点距反解，不做布尔减面 |
| 窑变生成超过 800ms     | 环节 5      | Worker 生成，超时降到 512²                      |
| 换图时要改代码         | 环节 1 起   | 清单 + 材质名 + 节点名                           |
| 切后台后倒计时误判     | 环节 1      | 冻结时钟，回来不追帧                             |
| 文化名称未经审核就公开 | 环节 7 之后 | 灰度前定稿并留来源                               |
