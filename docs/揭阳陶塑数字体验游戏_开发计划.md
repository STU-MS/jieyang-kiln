## 1. 现状

**代码**：v1.x 约 8800 行，围绕「车削杯体 + 拉坯 + 素烧 + 窑变贴图」建成。设计文档 v2.0 改为人物陶塑后，**玩法代码全部不适用**。

**保留的**：工程骨架。

| 保留 | 原因 |
|---|---|
| `package.json`、`tsconfig.json`、`vite.config.ts`、`vitest.config.ts`、`index.html` | 构建配置，与玩法无关 |
| `.github/workflows/ci.yml`、`release.yml`、`PULL_REQUEST_TEMPLATE.md` | 四段门禁与 PR 流程沿用 |
| `src/sim/math.ts`、`src/sim/rng.ts`、`src/sim/clock.ts` | 纯函数工具，与玩法无关 |
| `src/persist/storage.ts` | localStorage 封装，可改 `schemaVersion` 后沿用 |
| `src/assets/manifest.ts` 的**模式**（路径只在 manifest、玩法只认 id） | AGENTS.md 的规矩不变；文件本身重写 |
| `src/styles.css` 的设计变量（配色、间距） | 可沿用一部分 |

**删除的**：其余全部 `src/`。包括 `sim/` 里除上述四个外的所有文件、`render/`、`stages/`、`game/`、`data/`、`content/`、`audio/`、`ui/`、`App.tsx`。

**删除方式**：一个独立 PR，commit message 写明「按设计文档 v2.0 清场」。清场后 `pnpm test` 必须仍然绿（保留的四个工具文件有自己的测试）。

## 2. MVP 范围

| 阶段 | 做 | 不做 |
|---|---|---|
| ① 拆泥 | 四段滑杆、最小值、拆分动画 | 练泥、泥料质量变量 |
| ② 捏 | 四部位独立；点泥块播势场液态出生动画（末段交叉淡出到 morph 网格）；右侧抽屉按 `src/data/shape.json` 生成四部位滑杆；臂腿长短粗细守恒；退出保留状态 | 预设、点选、流体模拟、手腿独立塑形 |
| ③ 姿势 | 五个预设、补帧 | 自定义姿势、手部动作 |
| ④ 衣服 | 三件现成西式服装 | 东方服饰、叠穿 |
| ⑤ 阴干 | 颜色变浅过场 | 裂纹、天气、操作 |
| ⑥ 上釉 | 旋转视角、五种釉 + 无、笔刷大小、UV 贴图记录 | 混色、流淌、师傅提醒 |
| ⑦ 烧制 | 查表生成成品贴图、结果页对照 | 动画、火候、窑变随机、失败 |
| 通用 | 每阶段状态保存恢复、触屏 | 分享链接、分享图、知识卡、抽问 |

**二期候选**（不排期）：东方服饰自建、开窑动画、窑变随机、知识卡、分享、釉刷过厚流淌。

## 3. 技术选型

| 层 | 选 | 为什么 | 来源 |
|---|---|---|---|
| 渲染 | Three.js r169+（已在） | morph target 原生支持 | three.js 官方 morph 示例 |
| 人物基础网格 | MakeHuman / MPFB2 base mesh | **唯一 CC0 的参数化人体**，带 morph target、Mixamo 骨架、ARKit 表情 | https://static.makehumancommunity.org/about/license.html |
| 离线烘制 | Blender 无头 + MPFB2 | 从上千个 target 里挑 MVP 需要的，烘成小 GLB | kblood/CharacterCreator 的 `build_base.py` 做法 |
| 骨架跟随 | joints 侧车 JSON | morph 改形后骨骼位置要重算，否则姿势套上去部位错位 | kblood `base_body.joints.json` |
| 姿势 | VRMPose JSON | 纯数据，骨骼名 → 四元数 | https://pixiv.github.io/three-vrm/docs/types/three-vrm.VRMPose.html |
| 服装 | kblood/CharacterCreator 的 CC0 服装（T 恤、长袖、连衣裙） | 已 skinned、已跟 morph，**GPL-3.0 注意：只取 CC0 资产文件，不抄代码** | https://github.com/kblood/CharacterCreator |
| 笔刷 | 射线投射 → UV → canvas → `CanvasTexture` | Three.js 标准做法 | — |
| 参考（不抄代码） | HumanForge（MIT）、kblood（GPL） | 看它们怎么组织滑杆 → morph → 骨架 | — |

**不选**：Ready Player Me（2026-01 停服）、VRM/VRoid（条款禁做生成器）、MetaPerson（按量计费）。

## 4. 资产策略

**原则**：没有美术，全部用现成的。需要「做」的只有三样，都是程序生成。

| 资产 | 来源 | 体积预算 |
|---|---|---|
| 人物基础网格 + MVP 滑杆的 morph target | `kblood/CharacterCreator` 仓库的 `output/base_body.glb` 与 `output/base_body.joints.json`；许可依据该仓库 `LICENSE-NOTES.md`：`output/` 下 GLB 为 CC0-1.0（源全 CC0），代码 GPL-3.0-or-later 不取。裁剪：去贴图、只留滑杆用到的 morph、去眼睛 / 睫毛 / 牙齿等小件、`gltf-transform` 压缩 | 基础 ≤ 1 MB gzip；每部位增量 ≤ 300 KB；裁剪后体积实测见 PR |
| 骨架 joints 侧车 | 烘网格时同时导出 | ≤ 100 KB |
| 五个姿势 | 手写 VRMPose JSON | ≤ 20 KB |
| 三件衣服 | kblood CC0 资产 | 每件 ≤ 500 KB |
| 一团泥 / 四块泥 | Three.js `SphereGeometry` 缩放 | 0 |
| 泥土材质 | `MeshStandardMaterial`：CC0 漫反射贴图 `clay.albedo`（Poly Haven `clay_plaster`，512 缩图 18 KB）+ 程序噪声法线，数值表 `src/data/clay.json` | 贴图 18 KB，材质总预算 ≤ 50 KB |
| 拆分流体的势场 | 仓库自带 `three/examples/jsm/objects/MarchingCubes.js`，48³ 分辨率 | 0（不落地资产） |
| 釉层 UV 贴图 | 运行时 canvas | 512×512，运行时生成 |
| 成品贴图 | 运行时查表 | 512×512，运行时生成 |
| 五种釉的生釉色 / 烧成色 | 数据表 `src/data/glaze.json` | — |

**UV 贴图体积**：MakeHuman base mesh 自带 UV，直接用。釉层贴图和成品贴图都是 512×512，不预烘焙。

**GLB 压减**：只导 MVP 用到的 morph target（预计头 12 个、身 5 个、臂 3 个、腿 3 个，共 23 个），不要 MakeHuman 默认的上千个。用 `gltfpack` 或 `gltf-transform` 压。

## 5. 里程碑

| # | 里程碑 | 验收 |
|---|---|---|
| M0 | 清场 | 删除 v1.x 玩法代码；四段门禁全绿；仓库只剩骨架 |
| M1（进行中） | 人物能显示 | Blender 烘出 base GLB；Three.js 加载；23 个滑杆各能动 |
| M2 | 骨架跟随 + 姿势 | 滑杆拉到极端后套姿势，部位不错位；五个姿势可切换有补帧 |
| M3 ✅ | 拆泥 | 四段滑杆（拖分隔块、最小值、和恒为 100%）；拆分动画 1.6 秒（势场流体被拉开断裂、全程贴桌面、末段淡出到四块网格）；四块体积对应比例落在四个工位；确认后可重分；比例写入 `s1_split` 并可存档恢复。数值表 `src/data/split.json`、`src/data/clay.json` |
| M4（进行中） | 捏 | 点部位 → 变形动画 → 滑杆；退出重进保持；臂腿守恒联动 |
| M5 ◐ | 衣服 + 阴干 | 状态与规则层已落：`src/data/outfit.json`（三件 id）、换穿覆盖 / 脱掉语义、`src/sim/dry.ts` 单向门与 `dryColorAt` 插值、过场参数进 `src/data/dry.json`、存档可选字段 + 向前兼容。**待做**：衣物 CC0 资产、morph 跟随、穿模走查、材质过场接入——依赖 M1 网格 |
| M6 ◐ | 上釉 | 规则层已落：笔刷落点（圆形、单像素下限、越界裁剪）、厚度上限 3、同釉叠加、换釉覆盖、釉层进存档（游程编码）。数值表 `src/data/glaze.json`。**待做**：旋转视角、选釉面板、射线投射到 UV、贴图实时上材质——依赖 M1 网格的 UV |
| M7 ◐ | 烧制 + 结果页 | 规则层已落：逐像素查表、厚度 1–3 明度递减、露胎烧陶泥色、下线釉种按露胎降级、结果页对照数据。**待做**：结果页 UI、可旋转成品、生釉 / 烧成小图对照——依赖 M1 网格 |
| M8 | 触屏 + 体积 | 全流程触屏可走；GLB 总和 ≤ 3 MB gzip；首屏 ≤ 2.5s |

M0 先于一切。M1–M2 是技术风险最高的（morph + 骨架），先做。M3–M4 是玩法核心。

## 6. 测试重点（按 testing.md）

| 模块 | 必测边界 |
|---|---|
| 拆泥 | 四段和恒为 1；最小值生效；拖动分隔块不越界 |
| 守恒 | 臂/腿 长短 × 粗细 ≤ 分到的泥；拉到极限时另一根滑杆自动退 |
| 状态 | 每阶段保存 → 重载 → 数据逐字相同；`schemaVersion` 2 → 旧版 1 存档降级 |
| 釉层贴图 | 同一笔刷序列 → 贴图像素逐字相同；厚度上限 3 |
| 烧成查表 | 有釉像素 → 烧成色；无釉 → 陶泥色；厚度 1/2/3 明度递减 |
| 唯一性 | 1000 局四元组无重复 |

Three.js 渲染不进单测，走真浏览器走查。

## 7. 已知坑

| 坑 | 对策 |
|---|---|
| 骨骼缩放破坏蒙皮（子骨连带拉伸、法线错、脚浮空） | 不缩放骨骼，用 morph 改形 + joints 侧车重算位置 |
| 衣服和 morph 冲突穿模 | 衣服必须 skinned 到同一骨架、跟同一组 morph；kblood 自述只到 prototype，允许轻微穿模 |
| MakeHuman 写实脸不像陶塑 | 去掉头发/睫毛/眉毛 group，眉毛改几何凸起，材质 roughness 0.9 |
| GPL 传染 | kblood 只取 CC0 资产文件，代码一行不抄；HumanForge MIT 可参考 |
| 变形动画「液体感」 | 势场液态倒放，末段交叉淡出到 morph 网格（设计文档 §2.2）；参数在 `src/data/shape.json` 的 `birth` |
| 本地 `dist/` 假绿 | 沿用 testing.md，以 CI 为准 |
