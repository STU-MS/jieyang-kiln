## 1. 定位

**一局 6–7 分钟的浏览器 3D 游戏：把一团泥拆开、捏成一尊人物、摆好姿势、穿上衣服、上釉、进窑，开窑时看到自己预判的窑变对不对。**

三句话说明白：

- **拆泥定夸张**：泥是守恒的，头分多了身子就小。玩家不拉「头大」滑杆，玩家分泥。
- **捏是滑杆**：每个部位从球体连续变成默认形状，然后全部用滑杆调。没有雕刻，没有建模。
- **上釉看不到成品**：刷上去的是生釉色，烧出来是另一个色。玩家在预判。

### 1.1 目标

| 目标 | 验收 |
|---|---|
| 一局 6–7 分钟 | 内部试玩中位数 |
| 塑型阶段占一局 80% 时间 | 埋点 |
| 玩家能说出「揭阳陶塑脸手脚不上釉」和「釉烧前后颜色不同」 | 通关后抽问 |
| 每一局的人物几何唯一 | 滑杆向量 + 拆泥比例 + 姿势 + 釉层图 四元组不重复 |

### 1.2 非目标

- 不做练泥、揉泥。整备泥料这一段掠过，泥料直接可用。
- MVP 不做烧制动画，开窑只是结果页。
- MVP 不做东方服饰。先用现成的西式服装跑通。
- 不做手、腿的独立塑形。它们只跟身材走，只调大小长短粗细。
- 不做流体模拟。「液体变形」用势场（metaball + marching cubes）近似，见 §2.1、§2.2。
- 不做多人、排行榜、内购、UGC。

## 2. 流程

```
S0 整团泥
 └─ ① 拆泥 ────────→ S1 四块泥（头 / 身 / 臂 / 腿，各占比例）
      └─ ② 捏 ─────→ S2 小稿（逐部位：球 → 默认 → 滑杆）
           └─ ③ 姿势 → S3 摆好姿势的泥稿
                └─ ④ 衣服 → S4 穿好衣服的泥稿
                     └─ ⑤ 阴干 → S5 颜色变浅的干坯
                          └─ ⑥ 上釉 → S6 带生釉层的坯
                               └─ ⑦ 烧制 → S7 成品
```

顺序不可跳、不可倒。②内四个部位可任意顺序，退出再进入保留状态。

### 2.1 ① 拆泥

**目的**：把一团泥分成四块，分配比例就是夸张。

**交互**：
- 画面中央：一整块泥（椭球）。
- 下方：一根长滑杆，中间有三个可拖动的分隔块，把滑杆分成四段。每段长度 = 该部位的泥量占比。
- 四段固定顺序：头 / 身 / 臂 / 腿。每段有最小值（头部最小 5%，其余最小 10%），防止部位消失。
- 玩家拖分隔块，实时看到四段百分比。分隔块不能互相穿过：拖动时被相邻两段的最小值卡住。
- 确认后：中央泥块播放**拆分动画**（1.6 秒），像流体一样分成四块，各块体积对应比例，贴着桌面滑到桌上四个工位。
  - 「流体」用**势场（metaball + marching cubes）**表现，不做真流体模拟（见 §1.2）：四颗势场球从整团位置水平拉开，球把势场表面撑成一整团；两球距离变大时中段自动变细，超过约 2.3 倍半径就断裂——断口是算出来的，不是补帧补出来的。
  - 势场只在动画这 1.6 秒里存在。末段（进度 0.86→0.94）势场淡出、四块真实网格淡入，位置与半径已对齐，读起来是最后一点黏丝断开。
  - 全程只在水平面内发生：球心高度恒等于球自身的竖直半径，底部贴桌面——**不向上生长、不沿弧线弹跳**。
  - 静置的一整团、静置的四块、后续捏与上釉**全部走普通网格**（`SphereGeometry`），势场不参与任何玩法状态。
- 确认后仍可点「重分」：四块合回一整团，比例保留，滑杆恢复可拖。
- 参数全部在数据表，代码只读表：`src/data/split.json`（四段最小值、默认比例、整团 / 泥块尺寸、四个工位位置、拆分节奏、势场分辨率与半径）与 `src/data/clay.json`（湿泥贴图 id、色、粗糙度、金属度、噪声频率）。

**规则**：
- 四段之和恒为 100%。
- 拆分比例是**硬约束**：之后的滑杆不能改变部位总体积，只能在体积内改变形状。

**来源**：揭阳陶塑「人物大胆夸张，不循常规」；《老子出关》「人物形象比例调高，青牛比例压小」。分配材料是师傅的真实思维。

### 2.2 ② 捏

**目的**：每个部位从泥块变成默认形状，再用滑杆调整。

**进入方式**：
- 玩家点选一个泥块 → 进入该部位的操作界面 → **播放「球 → 默认形状」的连续变形动画** → 动画结束后滑杆可用。
- 四个部位各自独立。玩家可以退出当前部位去操作另一个，已操作过的部位**保持操作后的形状**继续渲染。
- 全部四个部位都播放过变形动画后，③ 解锁。滑杆可以不调。

**变形动画**：
- 动画由**势场（metaball + marching cubes，与 §2.1 同一套）**表现：部位网格先液化成泥团，把这条时间轴倒放，就是「球 → 默认形状」。
- 势场只在动画期间存在：时长 1.7 秒（`src/data/shape.json` 的 `birth.seconds`），采样、淡出区间也在这张表里。末段与真实部位网格交叉淡出，位置已对齐。
- 静置与滑杆走 morph target，不经过势场：原生 MakeHuman target + 运行时按骨骼权重生成的 `gen_*` target。
- 部位按骨骼权重切成头 / 身 / 臂 / 腿四块；切面不做封口片，靠部位之间轻微重叠遮挡。
- 泥块被点开后，部位按 `s1_split` 占比缩放（泥多的部位显示得大），在工位原位显示；缩放只影响显示，不改拆泥比例。
- **分团**：部位按网格岛（三角面连通性）分团，手臂两条、腿两条各成独立一团，每团一个独立势场。不用球间距离聚类：手臂垂在身侧时两臂空档比填充球半径还小，距离聚类一定连成一团。头 / 身若切出对不上的碎片岛，合回一团。
- **摆放**：模型正面是自身的 +Z。工位先绕世界 Y 转 90° 让正面朝摄像机；身 / 手 / 脚再绕世界 Z 转 90° 仰面平躺（背面贴桌、正面朝上），头部只转 Y 保持直立。落地由「部位自己的包围盒 × 当前变换」求最低点算，留 2 mm 余量避免与桌面共面闪烁。数值在 `shape.json` 的 `birth.pose`。
- **聚焦**：点开部位时镜头对准该部位包围盒中心，俯角按部位给（立着的头 18°、平躺的身 / 手 / 脚 46°），太浅的俯角看平躺部件只能看到侧边。

**滑杆规则**：
- 全部是滑杆，没有预设，没有点选。
- 每根滑杆有**上下限**，上下限由该部位分到的泥量决定。
- **粗细与长短守恒**（臂、腿）：加长必须调细，加粗必须缩短。滑杆之间联动，总量不超过分到的泥。允许有剩余泥（用不完）。
- 头和身：头分「大小 / 宽窄 / 胖瘦」，身分「高矮 / 胖瘦 / 壮弱」，各自在体积内变形，不涉及长短守恒。

**各部位滑杆**（MVP 范围）：

| 部位 | 滑杆 | 守恒 |
|---|---|---|
| 头 | 整体缩放（在分到的体积内）、脸宽、脸颊鼓出、耳朵大小、下巴长短、颧骨高低、鼻子高低、眉毛上翘、眼睛开合、嘴巴开合、胡须长短（几何件） | 体积守恒：脸宽拉大则脸颊自动变瘪 |
| 身 | 高矮、胖瘦、壮弱、肩宽、腰粗 | 体积守恒：胖瘦和腰粗联动 |
| 臂 | 长短、粗细、手大 | **长短 × 粗细守恒**，手大从臂的泥里扣 |
| 腿 | 长短、粗细、脚大 | **长短 × 粗细守恒**，脚大从腿的泥里扣 |

滑杆的具体数量、每个滑杆对应哪个 morph 通道，见 `src/data/shape.json`。通道权重规则：滑杆中心（0.5）不带动通道，向 `dir` 一侧走到滑杆端点（满行程）权重到 1；`dir` 正负两个通道各占一半行程。本文只定规则。

**来源**：五官滑杆对应「形神兼备」；胡须是几何件对应陈保国作品中「须髯飞霜」的捏塑做法。

### 2.3 ③ 姿势

**目的**：选一个姿势，各部位用补帧移动到对应位置。

**交互**：
- 姿势预设列表：站、坐、倚、跪、盘腿（MVP 五个）。
- 点选后，骨骼从当前旋转插值到目标旋转，部位跟随移动。时长 1 秒。
- 可换选。

**规则**：
- 姿势在衣服之前。因为衣服是 skinned 到骨骼的，骨骼没摆好衣服穿不上。
- 姿势只改骨骼旋转，不改 morph。

**来源**：揭阳陶塑工序「成型塑造」在前，「配釉施釉」在后；《老子出关》的「心」字坐姿。

### 2.4 ④ 衣服

**目的**：给人物穿一件衣服。

**交互**：
- 衣服列表（MVP：T 恤、长袖、连衣裙，现成 CC0 资产）。
- 点选即穿。
- 衣服跟身材 morph 一起变形，skinned 到同一骨架。

**规则**：
- MVP 一次穿一件，不叠穿。
- 衣服有独立 UV 区域，上釉时和皮肤分开。

**二期**：东方服饰（交领、道袍、短褐、袒胸）自建低模。

### 2.5 ⑤ 阴干

**目的**：泥稿变成干坯。

**交互**：点击「阴干」，过场。

**表现**：
- 全身材质从湿泥色（深、略有反光）变为干坯色（浅、无反光）。过渡 2 秒。
- 不做裂纹、不做天气、不做操作。

**规则**：纯视觉过场，不改任何数据。

### 2.6 ⑥ 上釉

**目的**：玩家用笔刷把生釉涂到衣服或身体上，看到的是生釉色，成品色要等烧制。

**交互**：
- 鼠标左键：笔刷涂釉。
- 鼠标右键拖动：旋转视角。
- 滚轮：缩放。
- 右侧面板：釉罐列表，每罐有标签和生釉色色块；笔刷大小滑杆。
- 涂在模型上，实时换算到 UV 贴图。

**规则**：
- **上不上是玩家的自由**。脸、手、脚可以涂。涂了不拦。
- 釉层是**一张 UV 贴图**：每个像素记「哪种釉、多厚」。
- 同一地方涂多遍 = 更厚。厚度上限 3 层。
- 不同釉叠在一起 = 上层覆盖下层（MVP 不做混色）。
- 没涂的地方 = 露胎，烧出来是陶泥色。

**生釉 → 窑变对应表**（MVP）：

| 釉 | 生釉色 | 烧成色 | 依据 |
|---|---|---|---|
| 灰釉 | 灰 | 红 | 来源：陈茂辉「灰色釉煅烧之后会变成红色」 |
| 绿釉 | 土黄 | 绿 | 来源：陈保国《五子佛》衣裤施绿釉 |
| 白釉 | 灰白 | 白 | 来源：《五子佛》白釉 |
| 水绿釉 | 淡灰 | 水绿 | 来源：《老子出关》衣袍水绿窑变釉 |
| 石墨釉 | 暗褐 | 黑 | 来源：《老子出关》青牛石墨釉 |
| 无 | — | 陶泥熏褐 | 来源：「陶泥烧成后色泽熏褐」 |

生釉色是**推断**（来源只说成品色），烧成色有来源。二期可加釉，须符合陶瓷呈色原理（铁出青、铜出绿、钴出蓝）。

### 2.7 ⑦ 烧制

**目的**：算出成品。

**交互**：点击「入窑」→ 结果页。

**算法**：
1. 读 S6 的釉层贴图。
2. 每个像素：有釉 → 查表得烧成色，按厚度调明度（厚 = 深）；无釉 → 陶泥色。
3. 生成成品贴图。
4. 结果页展示：可旋转的成品 + 「你预判对了吗」对照（生釉色小图 vs 烧成色）。

**MVP 不做**：烧制动画、火候曲线、窑变随机、失败。

**二期**：开窑动画；窑变随机（同一种釉，不同厚度、不同位置烧出来有深浅差异）。

## 3. 数据模型

每个阶段结束时保存一个状态。状态是纯数据，不含 mesh；mesh 由数据 + 资产在运行时生成。

```ts
type GameSession = {
  schemaVersion: 2;
  id: string;                    // 这一局的唯一 id
  s1_split: { head: number; body: number; arms: number; legs: number };  // 0–1，和为 1
  s2_shape: {
    head:  Record<MorphName, number>;   // 每个滑杆的值 0–1
    body:  Record<MorphName, number>;
    arms:  Record<MorphName, number>;
    legs:  Record<MorphName, number>;
    animated: { head: boolean; body: boolean; arms: boolean; legs: boolean };  // 变形动画是否播放过
  };
  s3_pose: { preset: PoseName };         // 'stand' | 'sit' | 'lean' | 'kneel' | 'crossLeg'
  s4_outfit: { id: OutfitId };
  s6_glaze: {
    layers: Float32Array;                // UV 贴图分辨率 × 厚度，每像素 0–3
    glazeIds: Uint8Array;                // 每像素哪种釉，0 = 无
    width: number; height: number;       // 贴图分辨率
  };
  s7_result: { previewUrl?: string };    // 成品贴图缓存，可重新生成
};
```

**唯一性**：`(s1_split, s2_shape, s3_pose, s4_outfit, s6_glaze)` 四元组（加贴图）决定一局的全部结果。

**保存时机**：每个阶段完成时、退出时、每 30 秒。

**状态与美术资源对应**：

| 状态 | 数据 | 视觉 | 资源来源 |
|---|---|---|---|
| S0 | — | 一团泥 | Three.js 椭球 |
| S1 | `s1_split` | 四块泥 | 四个椭球，体积按比例 |
| S2 | `s2_shape` | 变形后的网格 | MakeHuman morph target（CC0） |
| S3 | `+ s3_pose` | 摆姿势的网格 | VRMPose JSON |
| S4 | `+ s4_outfit` | 穿衣的网格 | kblood 服装（CC0） |
| S5 | 同 S4 | 材质换色 | 改一个 color |
| S6 | `+ s6_glaze` | 带生釉色的网格 | UV 笔刷画 canvas |
| S7 | 同 S6，查表 | 成品贴图 | 查表生成 |

## 4. 失败与反馈

MVP 没有失败。泥守恒是约束不是惩罚，玩家把 90% 的泥分给头，得到的就是一个头大身小的人，这是结果不是错误。

MVP 唯一的「反馈」是**预判对错**：结果页把生釉色和烧成色并排放，玩家自己看猜没猜对。

二期可加：釉刷太厚流到不该去的地方、阴干开裂（如果到时加回泥料质量变量）。

## 5. 技术约束

| 约束 | 要求 |
|---|---|
| 渲染 | Three.js，WebGL 2 |
| 人物基础网格 | MakeHuman / MPFB2 base mesh（CC0），**离线**用 Blender 烘成 GLB，只带 MVP 需要的 morph target |
| GLB 体积 | 基础网格 ≤ 2 MB（gzip 后）；每个部位独立 GLB，按需加载 |
| 贴图体积 | 釉层 UV 贴图 512×512；成品贴图 512×512 |
| 骨架跟随 | morph 改形后按 joints 侧车重算骨骼位置（kblood 的做法），再套姿势 |
| 姿势 | VRMPose JSON，纯数据 |
| 服装 | skinned 到同一骨架，跟同一组 morph |
| 笔刷 | 鼠标在模型上投射 → UV 坐标 → 画到 canvas → 作贴图 |
| 移动端 | 拆泥、姿势、衣服、上釉支持触屏；捏的滑杆支持触屏 |

## 6. 验收清单（MVP）

- [ ] 拆泥滑杆四段和为 100%，有最小值
- [ ] 拆分动画播放后四块体积对应比例
- [ ] 点选部位后播放变形动画，动画结束后滑杆可用
- [ ] 退出部位再进入，形状保持
- [ ] 四个部位都播放过动画后姿势解锁
- [ ] 臂、腿的长短粗细滑杆联动，总量不超分到的泥
- [ ] 姿势切换有补帧，部位跟随
- [ ] 衣服跟 morph 变形，不穿模（允许轻微）
- [ ] 阴干后颜色变浅
- [ ] 上釉可旋转视角、可选釉、可调笔刷、可涂
- [ ] 釉层贴图每像素记釉种和厚度
- [ ] 烧制结果页：有釉处查表、无釉处陶泥色、厚度影响明度
- [ ] 一局 6–7 分钟
- [ ] 全流程可在触屏完成
- [ ] 每阶段状态可保存、可恢复
