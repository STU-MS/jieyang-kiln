**文档用途**：面向程序、美术、策划与测试同学，作为揭阳陶塑数字化小游戏（以下简称「本游戏」）后续开发的一手依据。文中所有数值均为**开发期占位值（placeholder）**，需在灰度测试后由数值策划根据玩家通关率与卡关分布校准，校准结论须回写本表并升版。

**前置共识**：本游戏的产品定位是"**3—8 分钟一局的轻量工艺流程模拟器**"，而非写实陶艺仿真器。物理表现允许夸张（如泥胚突然塌成一团），目的是让玩家一眼看懂因果，而不是追求有限元级精度。

## 1. 项目概述
### 1.1 一句话定位
让玩家用五个玩法环节走完一只揭阳陶杯从泥到器的全过程，在"水土配比—湿度环境—火候窑变"三股随机力量的夹缝里，做出一只属于自己、且世上仅此一只的杯子。
### 1.2 设计目标（可验收）
1. **科普目标**：玩家通关后，能说出揭阳陶塑区别于普通陶艺的至少 2 个特征（如本地泥料含石英比例高、素烧温度带偏中温、釉色以青灰与酱褐为基底）。验收方式：通关后弹"知识卡"，次日复访时随机抽问，答对计入用户档案。
2. **玩法目标**：单局时长 3—8 分钟，新手首通率 ≥ 55%，核心环节（塑型、施釉、窑变）的次日复访率 ≥ 25%。
3. **留存目标**：窑变结果 100% 唯一（种子化随机 + 玩家操作序列共同决定），可生成分享图与 3D 预览。
4. **文化目标**：所有本地化表述（泥料名、釉色名、器物名、工序口诀）需经揭阳本地陶艺师傅或非遗相关工作者审核，审核意见留痕入档。
### 1.3 非目标（明确不做，避免后期需求蔓延）
- 不做多人联机、不做排行榜、不做氪金内购；
- 不做陶瓷历史长篇叙事，文化点以"卡牌 + 旁白语音"形式轻量承载；
- 不做真实窑炉结构模拟、不做化学分子式层面的烧制仿真；
- 不做用户自定义上传图案或 UGC 内容（规避审核风险）；
- 不做 VR 版本；移动端通过手机浏览器访问时降级为简化交互版。
### 1.4 平台、运行环境与性能基线
**本游戏是纯 Web 项目**，不依赖任何客户端下载、不接入小游戏封闭容器、不发版。玩家从任意渠道拿到链接即可开玩，版本更新随刷新即时生效，这也是选择 Web 的首要理由：**没有审核周期，文化内容纠错与数值热修的响应速度最快**。
| 项目 | 要求 |
| --- | --- |

### 1.5 浏览器侧必须处理的现实限制
| 限制 | 具体表现 | 应对方案 |
| --- | --- | --- |
| 后台标签页冻结 | 玩家切到别的标签页，requestAnimationFrame 与 setInterval 被整体暂停，回切后时间条"跳变" | 用 `document.visibilitychange` 监听，暂停即冻结本局时钟，回切不补偿、不追赶 |
| 自动播放策略 | 音频未经过用户手势时无法播放 | 首屏点击"开始"按钮时统一调用 `audio.resume()` 解锁，之后的音效无需再次解锁 |
| 内存回收 | 长时间游玩或反复重开导致老杯具纹理不释放 | 杯具纹理缓存上限 32 张，LRU 淘汰，离开环节时显式 `dispose` 几何与材质 |
| 高刷屏 | 144Hz 屏上按帧推进的计时器速度翻倍 | 所有计时走 `performance.now()` 差值累加，禁止按帧计数 |
| 省电模式 | CPU 降频导致粒子与音频卡顿 | 检测连续 3 帧耗时 > 50ms 自动降级粒子数量与纹理分辨率一档 |
| 移动端手势冲突 | 页面整体随拖拽滑动、误触返回 | 转台与施釉区 `touch-action: none`，其余区域恢复滚动 |

## 2. 文化内核与本地化内容
### 2.1 揭阳陶塑的三个"必传点"
为避免做成换皮通用制陶游戏，以下内容为本项目的文化硬约束，不可被通用陶艺内容替换：
1. **泥料来源**：揭阳陶塑选用本地**赤红色地格土**，选泥时要清除杂质，并把产地不同、成型与煅烧性能不同的陶土搭配成符合要求的坯体。地格土含铁量偏高，可塑性中等，烧成后胎质偏硬、吸水性低——这是"水土比"机制的现实依据。
2. **烧制逻辑**：先晒干低温素烧，后以**中温施釉烧制**为主。素烧须彻底排出结晶水与有机质，否则釉烧时残留气体逸出会造成釉面针孔与起泡；素烧过高则胎体趋近瓷化、吸水性下降，釉料附着不良而剥釉。这一前一后的因果链是本游戏环节 4 与环节 6 的核心张力。
3. **素胎与色釉的对比**：人物类作品脸部、手脚、躯干不施釉，保留陶土坯体原色与质感，捏塑痕迹与刀法清晰可见；衣饰、山石等才施满窑变色釉。本游戏虽做杯具，也须保留这一语言：杯内壁与口沿留素胎、外壁施釉，玩家若通体厚釉会被师傅提醒"把泥的本色盖住了"。
4. **釉色谱系**：以青灰、酱褐、米黄为基底，辅以铁锈斑与草木灰自然流淌，忌用大红大绿等脱离本地语境的配色。
5. **造型审美**：风格圆润喜庆、人物造型夸张，精拙粗细对比鲜明。杯具不设规定器形，拉坯时的虚影只作对照。
### 2.2 内容来源与审核红线
- **泥料、釉方、口诀**：从《揭阳工艺美术志》《潮州陶瓷史》及公开非遗申报材料中抽取，来源章节写入"图鉴"备注，禁止虚构历史年代与传承人语录。
- **工艺准确性**：塑型顺序、素烧与釉烧的分段、釉料需施于素胎等流程不可错置；错误流程应触发"师傅提醒"弹层，而非直接判负。
- **红线**：不得使用宗教祭祀器具外形、不得模仿现存文物纹样、不得出现地域对立表述。涉及"古法秘方"的内容一律只做原理性展示。
### 2.3 叙事壳与角色设定
- **主角**：玩家扮演一位外来学徒，跟随"陈师傅"（虚构角色，中年、左撇子、口头禅"泥是有脾气的"）学做第一只杯。
- **载体**：师徒对话以弹层短句呈现，每局总计约 400 字，不强制阅读，可一键跳过。
- **世界观边界**：仅做"学艺—出师"一条线，不展开家族史、不引入恋爱/争斗分支。

## 3. 核心玩法：五步主流程
### 3.1 流程总览
```
[环节1 调配陶土] → [环节2 拉坯塑型]
     ↓                    ↓
[环境：湿度波动层]    [环境：温湿度耦合层]
     ↓                    ↓
[环节4 晒干与素烧] → [环节5 配釉施釉] → [环节6 成型煅烧 + 窑变]
                                                       ↓
                                              生成唯一杯具 + 分享图
```
主流程是调配、拉坯、晒干素烧、配釉、煅烧五步。下文「环节 4 / 5 / 6」仍指晒干、配釉、煅烧，编号沿用。
**强制规则**：五步顺序不可跳、不可颠倒。若某环节失败（见 §5），玩家可「重做本环节」或「重开一局」，不消耗额外体力类资源（本游戏无体力系统）。拉坯塌了还可以回去调泥。
### 3.2 通用交互规范
- **统一输入**：拉坯为右键转视角、左键按住拖动塑形、滚轮或滑条调转速，并可在整体 / 内外 / 抹平三种手法间切换。其余点击类环节为单次点按，数值类环节为滑块。
- **撤销与容错**：各环节不提供逐步撤销。所有环节都提供「重做本环节」。拉坯塌了还可以重做这一步，杯子回到直筒，泥料不变。
- **反馈三层**：每个操作同时给出①视觉（泥色变化、刀具痕迹）②听觉（踩泥声、转盘电机声、窑火噼啪）③数据（顶部状态条实时浮动）。**任何单一反馈不可成为唯一提示通道**，以保证色弱与听障玩家可正常游玩。
- **自动存档点**：每完成一个环节写入一次存档，断线重连从最近完成的环节开始。
### 3.3 环节 1｜调配陶土（Clay Mixing）
**玩法目标**：在有限预算内，为一只杯调配出"可塑而不塌、干而不裂"的泥料。
**界面构成**：
- 左侧：3 种本地泥料卡片（赤红地格土、浅色高岭土、淘洗陈腐旧泥），各标注含砂量、可塑性、含铁量、单价，卡片副标题写明产地（如"揭阳本地·含石英与铁质偏高"）；
- 右侧：3 个量杯滑块（每种泥料 0—100 份）+ 1 个水量滑块（0—40 份）；
- 底部：实时状态条 4 条（可塑性、干硬度、含铁量、成本），调配过程中即时刷新。
**玩家操作**：拖动滑块 → 点击"揉泥"按钮 → 进入 3 秒揉泥小游戏（快速连点 + 节奏提示圈）→ 输出一团泥并显示泥团 3D 预览。泥团材质须呈赤红偏黄，禁用灰白瓷泥质感。
**数值框架（占位，需调参）**：
| 输出属性 | 公式（示意） | 影响去向 |
| --- | --- | --- |
| 可塑性 P | 0.5×高岭土占比 + 0.2×陈腐泥占比 − 0.6×水量 | 环节 2 杯壁能不能撑住 |
| 干硬度 H | 0.4×地格土占比 + 0.3×水量 − 0.2×环境湿度 | 环节 4 开裂概率、环节 6 烧结完整度 |
| 含铁量 I | 地格土占比 × 0.7 + 水量 × 0.05 | 环节 6 釉下呈色基底、窑变红褐倾向 |
| 成本 C | 各泥料单价×份数之和 | 仅影响本局"师傅满意度"评价分 |
**胜负判定**：本环节无失败，只有"泥团品质档位"：优（P、H 均落在甜蜜区）、良（一项越界）、劣（两项越界，默认后续环节坍塌/开裂概率 +15%）。**水量为 0 时直接判劣并提示"干泥不成型"，但允许继续**——这是故意保留的"玩家自找苦吃"路径，用于成就收集。
### 3.4 环节 2｜拉坯塑型（Throwing）
**核心机制**：杯壁按受力实时决定会不会塌。不规定器形，不计时。
**界面**：可环视的陶艺转台，中央为车削杯壁。右键拖动看杯。滚轮或右侧滑条调转速，范围 0–800，停下也能塑，只是跟手更慢。左键按住并拖动才施力，松手即停。拖动时从鼠标处伸出箭头，指向这一下的运动方向，泥沿这个方向走。贴外壁向上、向内托时，接触点以上的泥一起升高并向内收。
**手法**：三种可切换工具——**整体**（默认，柱向连带塑形）、**内外**（主要改半径）、**抹平**（熨平局部起伏）。桌面与触屏共用同一套指针逻辑。
**虚影**：半透明参照杯留在场中，只供对照，不作为过关形状。口、腹、足的刻度只显示当前半径。玩家随时可以确认，按当前形状进入晒干。
**体积**：每个受力点名下的泥体积在开拉时定死。外半径为 R、壁厚为 t、沿母线的材料长度为 L 时，体积是 π(2Rt − t²)L。R 或相邻点的距离变了，就反解 t。口沿甩大、点被拉开时壁变薄；点挤到一起时壁变厚。厚到当前半径里放不下时，外半径再往外涨，体积仍保持不变。
**受力**：水平方向是黏性引力，把相邻点的半径差拉回成形时的差值。竖直方向只有斥力：下面的点把上面的点往上顶，上面的点把下面的点往下压；间距一旦拉开，没有力再把它拉回去。另外还有重力和随转速、半径增大的离心力。撑不住就当场塌。
**塌了之后**：可以重做这一步（回到直筒，泥料不变）、回去调泥，或重开一局。知识卡进度保留。
**转速的代价**：转速越高，离心力越大，泥也越跟手。高速把口沿甩开，是这一环节的主要风险。
### 3.5 环节 4｜晒干与素烧（Drying & Bisque Firing）
**本环节是"环境变量显形"的主舞台**，由两阶段组成：
**阶段 A · 阴干（被动等待 + 轻交互）**：
- 界面为晾坯架，玩家可选择 3 个摆放位（通风处 / 阴凉处 / 日光下），每个位置有独立的温湿度实时读数；
- 玩家可在倒计时内"翻面"一次（改善两侧干湿差），或"遮盖"一次（应对突降湿度）；
- 玩家**不可加速**干燥，强行吹干（道具）会提高开裂风险，该道具默认锁定，仅在新手第 3 局后解锁。
**阶段 B · 素烧（主动控温）**：
- 温升曲线分 3 段（排湿段 0—300℃、氧化段 300—600℃、烧结段 600—900℃），每段需玩家拖动温度指针跟踪绿色目标带；
- 偏离目标带 5s 以上 → 胎体气孔率异常 → 环节 6 釉面出现针孔与橘皮；
- 超过上限温度 20℃ 以上 → 素胎过烧结化、发脆，环节 6 煅烧时**直接碎裂失败**。
**环境耦合规则**：环境湿度每升高 10%，阴干阶段所需时长 +8%，且素烧排湿段的目标带宽度收窄 15%（更难控温）。**这是"随机性影响后续"的第一条硬链路**。
**为什么环境在本游戏中是"真随机"而非装饰**：揭阳属亚热带季风性湿润气候、海洋性气候明显，年平均气温约 22.7℃；多年平均相对湿度 78.1%，各月相对湿度在 73%—90% 之间浮动；4—9 月降雨量占全年 80%—85%，冬春则可能出现干旱或早春低温阴雨。也就是说，同一只杯子在十月做和在四月做，晾干与烧成完全是两回事——这正是本游戏把"看天做陶"做成玩法的现实依据。以上数值为气候基线，具体月份区间须以揭阳市气象站最新 20 年统计资料为准，游戏内取值需在数据表中留版本号。
### 3.6 环节 5｜配釉施釉（Glazing）
**玩法**：从 6 种本地釉方（青灰釉、酱褐釉、米黄釉、铁锈花釉、草木灰釉、无光白釉）中**任选 2 种叠加**，分别设定浓度与施釉层数（1—3 层），再用笔刷在 3D 杯体表面局部补釉或点彩。
**资源约束**：釉料库存有限（由本局知识卡收集度与师傅好感度决定），强迫玩家在"全杯匀釉"与"局部彩绘"之间取舍。
**两个传导关系**：
1. 素胎气孔率过高 → 釉料吸收过快 → 局部露底，玩家需在露底区补釉，消耗额外库存；
2. 釉层过厚（总层数 > 4）→ 煅烧时流釉挂足，成品扣分，且**圈足被釉粘住的概率上升，导致环节 6 开窑时粘底失败**。
**判定**：施釉均匀度低于 40% 时，师傅弹层提醒"釉没吃住"，玩家可选择无视——无视不阻断流程，但窑变结果中釉色分层加重。
### 3.7 环节 6｜成型煅烧与窑变（Firing & Kiln Transformation）
**本环节由两个完全不同性质的系统拼合**：可控的"火候曲线" + 不可控的"窑变随机"。
**阶段 A · 火候曲线（玩家可控）**：
- 曲线 4 段：升温 → 氧化 → 保温 → 冷却，玩家分别设定**峰值温度**（1080/1120/1160/1200℃四档）与**保温时长**（0—4 小时）；
- 峰值温度须与釉方适配：青灰釉适配 1120—1160℃，酱褐釉适配 1080—1120℃。错配不报错，但结果明确劣化（温度过低 → 釉面哑光发涩；过高 → 流釉失形）；
- 冷却速率过快 → 胎釉应力开裂；过慢 → 能耗虚高（仅影响评价分，不影响成品）。
**阶段 B · 窑变（随机，玩家不可控）**：
- 系统根据以下输入生成唯一结果：`本局随机种子 + 含铁量 I + 釉方组合 + 峰值温度 + 保温时长 + 窑内气氛(随机) + 杯体几何哈希`；
- 输出维度：主色相偏移量、斑纹类型（铁锈斑/兔毫纹/油滴纹/无）、斑纹密度、光泽度、釉面流动方向、偶发瑕疵（针孔/橘皮/轻微变形）；
- **唯一性保证**：所有随机走 seeded RNG，玩家操作序列作为附加盐值，理论上全服无完全同款；
- **视觉实现**：优先用程序化纹理（噪声贴图 + 顶点色混合）而非预烘焙 6 张贴图——既保证唯一性，也避免贴图爆炸。
**结算**：开窑动画 6 秒，依次揭开保温棉 → 露出杯具 → 镜头环绕一周 → 弹出"你的杯"档案卡（器形评分、釉色评分、唯一编号、知识卡收集数）。

### 4.2 季节与天气：以揭阳实况为基线
**季节分区（数据来源：揭阳市气象站 2001—2020 年统计、惠来海洋站多年实测，游戏内须保留引用出处）**：
| 季节 | 月份 | 基础湿度区间 | 平均温区 | 主天气特征 | 素烧排湿段难度 | 对玩家的实际影响 |
| --- | --- | --- | --- | --- | --- | --- |
| 春季（含回南天） | 2—4 月 | 78%—88% | 约 15—22℃ | 低温阴雨、回南天、雾多发于 2—4 月下半夜至清晨 | 最窄目标带 | 阴干最慢，坯体易返潮，新手引导默认避开该季 |
| 前汛期（龙舟水） | 5—6 月 | 80%—90% | 约 25—28℃ | 连续性降雨、雷雨大风 | 窄 | 翻面/遮盖次数 +1，湿度上限最高 |
| 盛夏（含热带气旋） | 7—9 月 | 73%—85% | 约 28—33℃ | 短时强降雨、雷雨大风、台风外围影响 | 正常 | 体感闷热，蒸发快但突雨频繁，干燥不均风险高 |
| 秋季 | 10—11 月 | 60%—73% | 约 22—27℃ | 晴多雨少，10 月起进入干季 | 正常 | **推荐首发体验档**，条件最友好 |
| 冬季 | 12—1 月 | 55%—70% | 约 12—18℃ | 冷空气南下、偏北风、偶有低温阴雨 | 正常 | 蒸发过快、昼夜温差大，坯体收缩不均，开裂风险 +5% |
> 校验要点：表中"基础湿度区间"是按气象站公开数据的合理取整，用于游戏数值，**不可作为气象结论对外引用**；正式上线前由策划对照最新《揭阳市气候公报》逐格复核，并在"图鉴·气候"页注明数据年份。
**天气对玩法的影响举例**：
- **回南天**：环境湿度长时间维持高位，遮盖布效果减半（湿度仍缓慢上升），迫使玩家延长阴干而非硬烘；
- **冷空气南下**：室温在数小时内明显下降，坯体表面与内部温差拉大，翻面操作的容错窗口缩短；
- **雷雨大风**：强风直吹会带走坯体周围饱和水汽层，表面急干结"硬壳"、内部水分排不出——玩家若用风扇正对吹，即触发 §5.2 的龟裂惩罚；
- **热带气旋外围**：降雨持续且风力渐增，晾坯架有被吹倒的可能（见 §4.3 事件 7）。
### 4.3 突发小事件表：全部基于现实陶瓷工艺与揭阳气候
**设计前提：每条事件都必须是"现实中真会发生、且陶工真有应对办法"的事**，不允许出现电压不稳、程序报错、"窑神不高兴"等架空或玩笑式内容。每条事件都给出可识别的预兆、可执行的操作、成功的外形奖励、失败的外形后果。
#### 阴干阶段（发生在环节 4 阶段 A）
| 编号 | 事件（现实来源） | 预兆（提前 2—3s） | 玩家应对（限时 5s） | 成功结果（外形） | 失败结果（外形） |
| --- | --- | --- | --- | --- | --- |
| 1 | **突降雨势转大**——揭阳 4—9 月降雨集中，午后雷阵雨突发 | 天空转暗、风声渐起、仪表湿度开始爬升 | 从工具区拖出塑料布覆盖坯体 | 坯体保持原湿度，无异常 | 表面回潮发暗、杯口局部软化变形 |
| 2 | **回南天返潮**——暖湿气流涌入，墙面地面出水，坯体吸湿 | 地面出现水痕、读数持续缓升、师傅提醒"湿气又上来了" | 把坯体从地面搬至离地支架 | 底部干燥均匀，无底足积湿 | 底足长期积湿，烧成后底部泛黄、边缘起翘 |
| 3 | **冷空气突至**——冬季寒潮南下，降温明显 | 温度计快速下降、画面起薄雾 | 用保温棉包裹坯体侧部，减缓降温 | 温差受控，坯体完整 | 表面与内部收缩不均，出现贯穿性细裂纹 |
| 4 | **晨雾未散即搬动**——雾多发于 2—4 月下半夜至清晨 | 环境变为浓雾、湿度读数逼近 90% | 推迟搬动，等待雾散（计时暂停 10s） | 坯体状态不变 | 表面附着游离水，后续素烧排湿段时长 +15% |
| 5 | **风扇正对直吹**——陶工常识：干燥区风速宜控制在 0.5—1m/s，忌直吹 | 玩家主动开启风扇且角度对准坯体 | 调整风扇角度，改为反射板循环送风 | 表面与内部同步脱水 | 表面急干结硬壳、内部水分排不出，形成龟裂纹 |
| 6 | **坯体发现微裂纹**——干燥后期最常见的失手 | 坯体表面出现一条白色细线、无音效 | 用同配方湿泥浆填入裂纹并抹平，再缓慢回潮 | 裂纹闭合，成品留下极淡痕迹（收藏家加分） | 裂纹继续扩展，杯体在素烧时沿裂纹崩开 |
| 7 | **强风刮倒晾坯架**——台风外围与雷雨大风期常见 | 画面风力图标持续增强、架体晃动 | 拖拽固定支架稳住晾坯架 | 坯体无损 | 坯体倾倒磕碰，口沿出现一处缺口（烧成时成为应力点） |
#### 素烧阶段（发生在环节 4 阶段 B）
| 编号 | 事件（现实来源） | 预兆 | 玩家应对（限时 5s） | 成功结果 | 失败结果 |
| --- | --- | --- | --- | --- | --- |
| 8 | **排湿段升温过快**——残留水分急剧汽化、体积膨胀，最易导致坯体崩裂 | 窑内压力表微跳、仪表温度爬升速率超标 | 松开升温滑块，降回目标带 | 水分缓慢排出，气孔率正常 | 坯体内部应力过大，出现隐性暗裂（煅烧时才会爆开） |
| 9 | **入窑水分偏高**——坯体含水率应低于约 5%，否则高温瞬间汽化会炸裂 | 开窑门前提示"指甲划一下还有湿润感" | 推迟入窑，追加一段阴干 | 胎体安全 | 窑内爆裂声，杯体碎成数块，本环节失败 |
| 10 | **窑内温差过大**——装坯过密或窑位不当，局部温度不均 | 窑内热力图出现冷斑 | 调整杯体在窑内的位置（拖拽换位） | 受热均匀，烧结一致 | 杯体一侧过烧软化、一侧欠烧发脆，成品明显歪斜 |
| 11 | **烟囱排烟异常**——有机物氧化未完全时持续冒黑烟；正常应为白→淡黄→透明 | 烟囱颜色变化提示 | 降低升温速率、增大进氧量 | 有机物充分氧化，胎色洁净 | 碳素残留，成品釉面出现烟熏黄斑 |
#### 煅烧阶段（发生在环节 6）
| 编号 | 事件（现实来源） | 预兆 | 玩家应对（限时 5s） | 成功结果 | 失败结果 |
| --- | --- | --- | --- | --- | --- |
| 12 | **冷却过快（惊釉）**——600℃以下严禁强制风冷，温差应力会引发惊纹或炸裂 | 玩家主动开启窑门且温度仍在高位 | 关闭窑门，改为分段缓冷 | 胎釉应力释放充分，釉面完整 | 杯体出现网状惊纹，严重的当场炸裂 |
| 13 | **还原气氛不足**——含铁量偏高的泥料在弱还原下易泛黄，需气氛介入时机得当 | 烟气颜色提示、仪表"气氛"读数偏低 | 在正确时机（氧化完成后）微调进气阀 | 呈色正常，青灰/酱褐基调到位 | 成品泛黄或出现黄斑，含铁量高的泥料尤为明显 |
| 14 | **窑内烟气倒流**——会直接熏蚀釉面，钙含量高的釉料更甚 | 风向图标反转、窑口出现黑烟回灌 | 调整排烟通道开关 | 釉面洁净 | 釉面被熏蚀，出现局部黑斑或"火刺"状黄褐粗糙区 |
| 15 | **高温保温时间不足**——热量未穿透坯体中心，即"生烧"，表现为釉面无光、发黄、敲击声浑浊 | 保温计时器剩余时间归零但窑内温差读数仍高 | 延长保温 1 小时 | 烧结充分，釉面玻化良好 | 成品釉面哑光发涩、局部泛黄、胎体强度偏低 |
| 16 | **高温段升温过快**——釉面玻化过早会把还原气氛封在釉层内，形成针孔与开口釉泡 | 温度曲线斜率异常、釉面预览出现密集小点 | 放缓升温速率 | 气体充分逸出，釉面平滑 | 釉面出现针孔，密集时呈橘皮状，即"桔釉" |
### 4.4 事件的平衡与校验
- **可归因**：失败弹层必须写明"现实原因 → 外形表现 → 下次怎么避免"，例如"风扇正对吹 → 表面结硬壳 → 改用反射板循环送风"。
- **概率分档**：阴干阶段每局 0—2 次、素烧阶段 0—1 次、煅烧阶段 0—1 次；同一局内不出现 2 条同环节事件，避免叠加挫败。
- **难度挂钩**：新手前 3 局事件概率减半，且预兆时长延长至 4s；熟练档（累计通关 5 次以上）恢复正常，并解锁"无事件"练习模式。
- **失败不是惩罚而是课程**：事件失败只产生外形后果，不扣抽象分数；外形后果会进入"残器谱"收藏，是收集向玩家的主要目标。
- **平衡红线**：单次事件对最终评分的影响幅度 ≤ 6%，且必须低于玩家操作失误的影响幅度，否则玩家会感到"我的努力没用"。
### 4.5 随机性的可见与不可见
- **可见随机**：天气、环境仪表、事件预兆、师傅提示——玩家能看见并作出反应；
- **不可见随机**：窑变内部细节（气氛波动、结晶方向、窑位微小温差）——刻意不可见，否则"随机"就退化成"可算"；
- **不可操作化**：严禁把事件设计成"猜天气""猜数字"，所有应对都应是陶工真实动作（盖布、搬架、调整风量、放缓升温、延长保温），让玩家在玩的过程中学会这五件事。

## 5. 失败、惩罚与反馈
### 5.1 失败等级定义
| 等级 | 名称 | 触发条件 | 处理方式 |
| --- | --- | --- | --- |
| L0 | 完美 | 全环节无越界 | 解锁隐藏知识卡 + 成就"泥是有脾气的" |
| L1 | 正常通过 | 评分 ≥ 60 | 正常结算，生成杯具 |
| L2 | 带伤通过 | 评分 30—59，或存在崩边/针孔 | 杯具生成但外形有可见瑕疵，可入库 |
| L3 | 环节失败 | 泥胚坍塌、素胎过烧、开窑粘底/碎裂 | 环节内重试，不计作失败局 |
| L4 | 流程失败 | 单局累计重试 5 次仍未通过 | 弹出"师傅示范"自动演示，跳过本环节 |
### 5.2 惩罚必须落在"外形"上
用户明确要求：**所有失败与惩罚以"外形相关"为唯一落点**，即惩罚必须可见、可描述、可展示，不允许出现"分数-20"这类抽象惩罚。
**可执行的外形惩罚清单**：
| 成因 | 外形表现 | 对后续的影响 |
| --- | --- | --- |
| 水土比失衡 | 杯壁撑不住，当场塌下 | 重做这一步或回去调泥；成品若带伤通过则重心不稳 |
| 含水量过高 | 泥面水光、指印下陷 | 干燥时间 +，素烧排湿段更窄 |
| 晾坯磕缺口 | 口沿缺口 | 施釉不均、煅烧应力点 |
| 阴干过快 | 表面龟裂纹、胎体翘曲 | 釉面针孔、煅烧开裂概率 + |
| 素烧过热 | 胎体发脆、边缘起翘 | 煅烧时碎裂风险 + |
| 釉层过厚 | 流釉挂足、釉面橘皮 | 圈足粘底、开窑失败 |
| 冷却过快 | 胎釉微裂纹（惊釉） | 仅外观瑕疵，不影响可用性 |
### 5.3 反馈规范
- **失败不羞辱**：所有失败文案均为师傅第一人称口吻（"这里泥软了，扶不住"），**绝不使用"你错了""失败""笨"等字眼**；
- **失败要可归因**：每次失败弹层必须写明"成因 → 后果 → 下次怎么避免"三段，否则玩家无法学习；
- **失败不丢进度**：拉坯之后的失败，允许从本环节重做，且不重置已通过的环节；
- **失败可炫耀**：L2 的"带伤成品"单独归档为"残器谱"，是收集向玩家的主要目标之一。

## 6. 数据与存档
### 6.1 数据结构（TypeScript 示意）
```ts
type GameState = {
  seed: number;                    // 本局种子，决定天气与窑变基底
  season: 'spring' | 'preFlood' | 'summer' | 'autumn' | 'winter';  // 按揭阳实况分区，见 §4.2
  weather: Weather;
  clay: { P: number; H: number; I: number; C: number; recipe: Recipe };
  throwing: { radii: number[]; thickness: number[] }; // 体积按环保存；虚影只作对照，不写入过关目标
  drying: { placement: 0 | 1 | 2; flipped: boolean; covered: boolean };
  firing: { peakTemp: number; holdHours: number; curveDeviation: number };
  glaze: { layers: GlazeLayer[]; brushMask: Float32Array };
  result: { hueShift: number; pattern: Pattern; gloss: number; flaws: Flaw[] };
};
```
### 6.2 存档策略
- 单存档槽，本地 localStorage（存档）+ IndexedDB（杯具纹理缓存）双存储，写入异常时静默降级不中断游玩；
- 写入时机：环节完成、玩家主动退出、每 30s 心跳；
- 版本兼容：`schemaVersion` 字段必须存在，旧版存档加载失败时降级为"自动重新开一局并赠送知识卡×3"；
- **严禁**将随机种子、天气生成规则、配方数值硬编码在客户端明文——防作弊需走混淆 + 关键结果服务端校验（服务端只校验结果合理性，不参与过程，避免破坏单机体验）。
### 6.3 评价指标（后台埋点，不展示给玩家）
单局操作数、各环节重试次数、坍塌/碎裂触发点分布、泥料配比偏好、釉方组合 TOP10、平均通关时长、环节流失热力图。该数据用于数值调参，需在隐私政策中声明。

## 7. 美术与音频规范
### 7.1 美术风格
- **主基调**：粗陶质感 + 温润米白 UI，参考揭阳本地民居的灰瓦与夯土墙；
- **泥料材质**：粗糙度 0.85、次表面散射弱、法线贴图以手捏指纹为主，禁用光滑塑料感；
- **泥胚形变**：用骨骼蒙皮 + BlendShape 混合，单泥胚骨骼数 ≤ 24，形变在顶点着色器中完成；
- **杯具展示**：最终成品输出 3 组贴图（albedo / normal / roughness，均为 1024²），PBR 材质，支持旋转与缩放；
- **配色禁用表**：荧光色、纯黑（#000000）、高饱和品红——与本地陶塑语境冲突。
### 7.2 界面信息层级
- 一级：状态条（可塑性、湿度、温度）——**必须常驻可见**；
- 二级：操作按钮、资源数量——操作区附近；
- 三级：知识卡、师傅旁白——可折叠、可跳过；
- 禁止：弹窗套弹窗、倒计时与操作提示同时出现、超过 3 种动效并存。
### 7.3 音频
- 总音轨 ≤ 6 条同时播放；转台电机声随转速线性变频（DSP pitch，不预烘焙）；
- 关键节点音：揉泥（低频闷响）、刀具切削（高频刮擦，短促 < 0.3s）、窑火噼啪（随机颗粒噪声）、开窑（金属缓鸣 + 热气释放）；
- 静音模式：所有信息必须有视觉等效表达（见 §3.2）。

## 8. 开发拆分与里程碑
### 8.1 技术难点与应对
| 难点 | 风险 | 应对方案 |
| --- | --- | --- |
| 泥胚实时形变 | 顶点抖动、核显掉帧 | 目标骨架预烘焙 8 个 BlendShape + LOD 两级，距离相机 >2m 切低模；移动端 WebView 降级一档 |
| 窑变唯一纹理 | 组合爆炸、首屏膨胀 | 程序化噪声 + 参数化混合，纹理运行时生成并缓存到 IndexedDB，LRU 上限 32 张 |
| 坍塌判定的手感 | 太敏感=挫败，太松=没策略 | 按杯壁受力实时判定，塌了当场停，可重做这一步 |
| Web 包体与首屏 | 首屏慢、内存压力大 | 按环节动态 import 分包，音频走流式加载，首屏仅保留环节 1 资源 |
| 后台标签页冻结 | 切页后时钟跳变、事件超时误判 | 监听 visibilitychange 冻结本局时钟，回切不补偿不追赶 |
| 随机结果可复现 | 分享后结果不一致 | 全链路 seeded RNG，分享链接携带 seed 与操作摘要 |
| 触屏与鼠标双输入 | 两端手感不一致 | 同一套拖拽/捏合逻辑双端复用，转台区 touch-action:none |

### 8.2 里程碑（建议 10 周）

| 周次 | 里程碑 | 验收标准 |
| --- | --- | --- |
| W1—W2 | 玩法原型（Greybox） | 五步主流程可跑通闭环，数值为占位值，无美术 |
| W3—W4 | 核心手感 | 拉坯坍塌判定通过 5 名内部测试者盲测，认可率 ≥ 80% |
| W5—W6 | 美术与音频接入 | 主界面、泥料、杯具材质达标，静音模式可用，Chrome / Safari / Edge / 移动端四端首屏达标 |
| W7 | 窑变系统与唯一性 | 连续 1000 局无完全同款，纹理生成耗时 < 800ms |
| W8 | 文化内容审核 + 新手引导 | 审核意见 100% 闭环；新手 3 分钟内完成首通 |
| W9 | 性能与兼容性 | 覆盖 12 款机型 × 4 款浏览器（Chrome / Edge / Safari / Firefox），含桌面与移动端，中端机 45fps 达标 |
| W10 | 小范围灰度 | 100 名真实用户通过浏览器访问，首通率与复访率达成 §1.2 指标 |
### 8.3 需求边界清单（开发自测用）
- [ ] 五步顺序强制，不可跳关
- [ ] 拉坯不规定器形、不计时，虚影只作对照；确认后直接晒干
- [ ] 水土比真实影响杯壁能不能撑住；形状变了，泥的体积不变
- [ ] 环境变量至少覆盖季节、天气、环节内波动三层，季节分区符合揭阳实况（§4.2）
- [ ] 每个环节的玩家操作都对后续环节有可见影响（§3 每条传导关系均有 UI 提示）
- [ ] 所有失败均有外形表现，无抽象扣分
- [ ] 失败弹层含"现实成因—外形后果—下次如何避免"三段
- [ ] 16 条突发小事件全部有现实出处、全部有预兆与可执行应对、全部只产生外形后果
- [ ] 最终杯具 100% 唯一，可生成分享图与分享链接
- [ ] 色弱/听障/静音三模式均可通过主流程
- [ ] 桌面鼠标与移动触屏双输入行为一致
- [ ] 切到后台标签页再切回，本局时钟不跳变、事件倒计时不误判
- [ ] 不支持 WebGL 2 的浏览器有静态图文替代页，不黑屏
- [ ] 单局可 3 分钟内完成（熟练玩家）
